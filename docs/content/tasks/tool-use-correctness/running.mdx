# Running it

## 1. A key

```bash
cp .env.example .env
```

Fill in one of:

| Key | Gets you |
| --- | --- |
| `OPENROUTER_API_KEY` | many models through one account — [openrouter.ai](https://openrouter.ai/models) |
| `ANTHROPIC_API_KEY` | the first-party `claude-*` models |

That is the only credential needed. The model is *offered* a search tool but
never gets to use it — the moment it reaches for the tool, the item ends and
the call is recorded. The decision is the measurement, and it is made before
any result would come back, so there is no search API involved.

`.env` is gitignored. Anything exported in your shell wins over the file.

## 2. Build the task set

```bash
make data     # source datasets, about 38 MB, checksum-verified
make tasks    # build the 360 items
```

## 3. Run

```bash
llmsearchbench run --model qwen/qwen3.5-27b
```

It prints what it is about to do and roughly what it will cost, then asks
before spending anything:

```text
360 item(s) · qwen/qwen3.5-27b (OpenRouter) · effort high · roughly $0.19
Run it? [Y/n]
```

Useful flags:

| Flag | What for |
| --- | --- |
| `--limit 20` | a short smoke run before committing to the whole set |
| `--bucket no_tool` | run one bucket; repeatable |
| `--effort low` | cheaper, faster; also a fair thing to measure |
| `--no-resume` | start over instead of skipping finished items |
| `--yes` | skip the confirmation, for scripts |

`--limit` is spread across the three buckets, so a short run still measures all
of them. Start with `--limit 20`: it costs cents and catches a bad model id in
a minute rather than an hour.

### It resumes

Each attempt is written to `results/local/<model>-attempts.jsonl` the moment it
lands. If the run dies — rate limit, dropped connection, laptop closed — rerun
the same command and it picks up where it stopped. Runs cost real money; losing
them to a timeout would be the expensive kind of bug.

## 4. Score

```bash
llmsearchbench score --model claude-opus-5
```

*(Illustrative numbers — no run has been published yet.)*

Scoring is free and offline. It reads the attempts file, so you can rescore
after changing the scorer without paying for the run again.

## What you get back

Seven tables. Three are the correctness measurements; four are what the run
spent. From a real twelve-item run of Qwen3.5 27B:

```text
1. Decision                          Failure modes
memory     4   50.0%                 over-search (memory)   50.0%
search     4   75.0%                 over-search (no_tool)   0.0%
no_tool    4  100.0%                 under-search           25.0%
overall   12   75.0%                 adversarial accuracy    0.0%

2. Call quality                      4. Cost
items that called      5             total                      $0.0075
calls total            5             per 1,000 items              $0.63
well formed       100.0%             wasted on needless searches
                                                      $0.0004 (5.3%)
                                     per right decision       $0.00084
```

Plus tokens (input, output, and how much of the output was thinking), time
(mean, median, p95, max, throughput), and effort per bucket — output tokens,
thinking tokens, latency and cost broken out by prompt type.

Worth knowing about each:

**Cost** is computed from the catalogue price at scoring time, not stored, so
correcting a price does not mean re-running anything. **Wasted spend** is the
money that went on items the model should never have searched — the dollar
value of a bad tool policy. **Cost per right decision** is what makes models at
different prices comparable.

**Tokens.** Thinking tokens are reported separately where the provider breaks
them out, but they are *inside* the output total — reasoning models bill them
as output. Median and p95 sit beside the mean because one long answer distorts
a small sample.

**Effort per bucket** usually says the most: whether a model burns as many
tokens deciding not to search as it does deciding to.

**Answer accuracy** is only meaningful for the `memory` bucket. Nothing is
retrieved, so a `search`-bucket answer has nothing to be right from — a high
number there means the model knew it after all, which is itself worth seeing.

:::note[Twelve items is not a result]
The numbers above show the shape of the output. They rank nothing.
:::

## What a run costs

Roughly, for all 360 items:

| Model | Estimate |
| --- | --- |
| `claude-haiku-4-5` | under $1 |
| `claude-sonnet-5` | about $1.50 |
| `claude-opus-5` | about $3.50 |

No other cost: no search API is called. The exact figure depends on how much
the model thinks, which varies a lot between models.

## Adding a model

Models are catalogued in `src/llmsearchbench/providers/registry.py`, with their
prices:

```python
ModelSpec(
    id="openai/gpt-5",              # exactly as the provider names it
    label="GPT-5 (OpenRouter)",     # what the results table shows
    provider="openrouter",
    price_in_per_mtok=0.00,         # from the provider's pricing page
    price_out_per_mtok=0.00,
    priced_on="2026-09-22",         # when you last checked
)
```

The price is not optional. It feeds the published cost column, and a release
checks that no model would publish a cost of zero.

:::note[Routing changes results]
A model called through OpenRouter is not strictly the same as the same model
called first-party — tool-call formatting and default sampling can differ. The
route is recorded with the run. Compare like with like.
:::

## When it breaks

| Message | Fix |
| --- | --- |
| `ANTHROPIC_API_KEY is not set` | fill it in `.env`, or export it |
| `unknown model 'x'` | check `llmsearchbench models` |
| `no task set at …` | run `make tasks` |
| an OpenRouter error | the run stopped; rerun to resume from where it got to |
